# Animation improvement plans

Generated by the `improve-animations` skill (audit of the Astro site's motion:
`src/layouts/Base.astro` reveal engine, `src/components/Hero.tsx`, and the
hover/scroll motion across `src/pages/*.astro` + `src/styles/global.css`).

Each plan is self-contained — a model or person with zero context can execute it.
Plans only describe changes; they do not modify source until executed.

| # | Title | Severity | Category | Status |
|---|-------|----------|----------|--------|
| 001 | Respect prefers-reduced-motion in the Framer hero | MEDIUM | Accessibility | DONE |
| 002 | Tighten the portrait hover-zoom duration | MEDIUM | Easing & duration | DONE |
| 003 | Consolidate easing and durations into tokens | LOW | Cohesion & tokens | DONE |

## Recommended execution order

1. **001** — independent (only `Hero.tsx`); the highest-value fix (accessibility). Do first.
2. **002** — independent (portrait `duration-700 → duration-500`).
3. **003** — **run after 002** (it swaps the now-500ms hover literals for token references and pins the shared curve). Pure refactor, no visual change.

## Dependencies

- 003 depends on 002 (it expects the hover duration to already be 500ms).
- 001 and 002 have no dependencies and can be done in either order.

## Not planned (from the audit, deferred by choice)

- **Reveal timing tuning** (reveal ~500ms / stagger ~60ms, optional stronger curve) — LOW.
- **Hero Framer `y` shorthand → full transform** — LOW; negligible at current load.
- **Missed opportunities**: animate the mobile-menu open/close (opacity + `translateY(-8px)`, ≤200ms); add `:active` press feedback (`scale(0.97)`, ~140ms) on CTAs.
